Согласованный вид реестров

Одна цельная композиция за раз. Поиск, списки, наведение и «Сбросить фильтр» работают на вымышленных данных. Это образцы общих ролей; состав и расчёты реальных страниц сохраняются при адаптации.

Что здесь утверждено — роли и правила для агента
  • Шапка страницы — Отдельная шапка с иконкой, заголовком, пояснением и действиями справа. Новая страница использует общий PHP partial. registry.page-head
  • Вкладки статусов — Плоские вкладки со счётчиками и линией активного статуса; на узком экране прокручиваются внутри своей строки. registry.tabs
  • Рамка рабочего блока — Единая непрерывная рамка вокруг панели и таблицы. Шапка страницы находится отдельно. registry.card
  • Панель Найдено и фильтров — Панель внутри рамки: слева счётчик и при наличии флажок через штатный разделитель, справа сначала «Сбросить фильтр», затем фильтры, поиск последним. Высота растёт вместе с содержимым; появление сброса не сдвигает контролы. registry.toolbar
  • Поиск — IBM Plex Sans 12/500/16; отступ слева 31 px, постоянная иконка при focus. Поиск последний справа; «Сбросить фильтр» расположен перед фильтрами и появляется при изменении состояния. registry.search
  • Таблица и заголовки — Таблица с утверждёнными типографикой, фоном строк и заголовком. Колонки и предметные данные задаёт страница. registry.table
  • Закрепление панели и заголовков — Opt-in для закрепления панели и заголовков. Общий JS измеряет реальную высоту панели. registry.sticky
  • Выбор значения — Светлый закрытый select #FFFDF9 с рамкой #C8C0B5 и текстом #2E2923 в тон поиску; hover и pressed #F9F7F2 с рамкой #A8A196. Белый список сохраняет геометрию; выбранный пункт #F0EDE7, при наведении #EAE3D8. Управление клавиатурой и native select сохранены. registry.select
  • Кнопки шапки — Вторичные действия идут перед одним главным. Общий компонент задаёт размер, цвет, hover и focus. registry.actions
  • Флажок панели — Существующий общий класс для одиночного native checkbox с кликабельной подписью, без отдельной плашки. Если флажок предусмотрен страницей, он расположен слева после счётчика и существующего .filter-sep; без флажка разделителя нет. Исторический .rp-v014-hide-complete не использовать как образец новой страницы. registry.checkbox
  • Финансовая таблица — Утверждённый вариант таблицы для широкой финансовой записи. Состав колонок и итоги задаёт страница. registry.finance-table
  • Блок флажков — Группа и одиночный флажок панели используют одно правило размеров, текста и фокуса; обычный акцент коричневый. Только блок статусов рейсов с явным вариантом registry-ui-checkboxes--trip-status использует смысловые цвета. Native input сохраняет клавиатуру и доступное имя. registry.checkbox-group
  • Типографика данных — Основной 12/500/16.8; имена и суммы 12/600; дополнительный 11/500/15.4. IBM Plex Sans. registry.data
  • ID любой сущности — Общая колонка 64 px для #0000; настоящий ID не сокращается и не дополняется нулями. registry.id
  • Описание рейса — Колонка 240 px, 30 графем и …; полное значение доступно для чтения и поиска. registry.trip
  • Дополнительные данные — Дата счёта, водитель под перевозчиком, пояснения, контакты: 11/500/15.4. registry.secondary
  • Смысловые цвета — Согласованные жёлтый/чёрный, красный, мягкие красный и зелёный; hover без изменения геометрии. registry.palette
  • Предметные статусы — Выезды: фиолетовый, бирюзовый, зелёный, серый. Документы: Есть/НЕТ, несколько ТС, оплата и комплектность. registry.status
  • Фильтры, память и сброс — Одна кнопка «Сбросить фильтр» первой в правой группе при любом отклонении от начальных значений. Состояние отдельно по странице, пользователю, роли и компании; select и поиск не сдвигаются при появлении кнопки. registry.state
  • Прокрутка таблицы — Один вертикальный владелец, панель и заголовки закреплены вместе, горизонтальная прокрутка широкого содержимого. registry.scroll
  • Блоки размещения ФЭО — Opt-in таблица с нейтральной отключённой строкой, цветом и весом операции, естественным переносом цельных ID источника и согласованной сводкой вторичного поиска. Предметные ширины колонок задаёт FEO view. registry.placement-blocks
  • ID и название в одной строке — Одна строка из неизменного ID и названия с существующими primary/name ролями; длинное имя сокращается с полным title. Во вторичном поиске ФЭО тип стоит второй колонкой, все строки используют общий жёлтый warning, заголовок не наследует sticky основной таблицы. registry.inline-identity
  • Компактный попап реестра — Общая opt-in оболочка согласованных попапов: шапка 19/700, тело 12/16, футер с семантическими кнопками; вложенные формы и текстовые представления используют одни классы и сетку. registry.modal
  • Таблица внутри попапа — Таблица с системной внешней обводкой, заголовком и внутренней прокруткой до 300 px. Ячейки каждой строки начинаются на одном верхнем уровне. Предметные колонки определяет попап: при предпросмотре переноса Заявка, Вес нетто, Было, Станет; в истории выполненного переноса Заявка, Вес нетто, Было, Стало. registry.compact-table
  • Номер заявки в попапе — IBM Plex Sans 12/700, #131210, табличные цифры; все номера заявок показываются целиком и переносятся по границам номеров. registry.entity-id

Используйте общий CSS/JS и docs/ui/REGISTRY_CANON.md. Новые визуальные решения: предложение → песочница → решение OWNER → общий компонент → тест → каталог и витрина.

Границы согласования

Здесь показаны четыре переключаемых образца; полный перечень подключённых страниц находится в каталоге. Формы, подтверждение удаления, загрузки файлов и ожидание серверных операций требуют отдельных примеров. Функциональные фильтры «Компания» и «Квартал» руководителя в «Закрывающих документах» уже реализованы на утверждённом select; отдельно ожидает визуального решения только самостоятельный универсальный прототип таких фильтров.

Новая страница обязана использовать действующие решения из REGISTRY_CANON.md и каталога и пройти собственную проверку данных, поведения и отрисовки. Одно имя класса или пример витрины не доказывают соответствие.
